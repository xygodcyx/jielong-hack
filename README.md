# 接龙工作台

参考 `school_checkin` 的微信登录与签到流程，独立实现的本地 Web 工作台。优先支持接龙、签到和周期打卡。

## 项目文档与 AI 接手

- [完整项目与交接文档](docs/AI_HANDOFF.md)：架构、源码导航、接口协议、身份与存储、提交和调度状态、开发验证、排障、已知限制及接手步骤。

## 启动

需要 **Node.js 22.13+**，使用 pnpm 管理依赖。视频与音频校验另外需要 ffmpeg 中的 `ffprobe`。

```sh
pnpm install
pnpm dev
```

打开 [本地工作台](http://127.0.0.1:3210)。默认只监听本机地址。可复制 `.env.example` 为 `.env`，修改端口、监听地址等配置；启动命令通过 Node 的 `--env-file-if-exists=.env` 自动加载。

```sh
# macOS，按需安装视频探测工具
brew install ffmpeg
```

### 生产运行与 PM2

生产环境先构建，PM2 按 [ecosystem.config.cjs](ecosystem.config.cjs) 直接运行编译后的 Node 程序。PM2 已列入项目开发依赖：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm exec pm2 start ecosystem.config.cjs
pnpm exec pm2 save
```

不使用 PM2 时，在构建后运行 `pnpm start`。查看日志和更新代码后的重启：

```sh
pnpm exec pm2 logs jielong-studio
# 更新代码后先重新构建，再重启
pnpm build
pnpm exec pm2 restart ecosystem.config.cjs --update-env
```

配置固定项目工作目录，读取同一份 `.env`，以 **单实例 fork** 运行并在异常退出后重启。收到停止或重启信号时，服务停止接收新连接和定时调度，最多等待 60 秒让在途请求与后台任务完成；PM2 的强制终止等待为 65 秒。超时中断仍按既有状态恢复规则处理，不自动重发结果不明的签到。请保持单实例，避免 `pm2 scale` 或 cluster 重复执行计划。

原有 `.local/state.sqlite` 与附件目录继续使用，无须清空或迁移。首次从旧启动方式切换到 PM2 时，先停止旧进程，避免两个进程共用数据目录。若要设置开机启动，执行 `pnpm exec pm2 startup` 并按终端提示完成系统服务安装，再运行 `pnpm exec pm2 save`。完整选项见 [PM2 配置文档](https://pm2.keymetrics.io/docs/usage/application-declaration/)。

## 使用

1. 微信扫码登录，选择“我参与的 / 我发布的 / 我收藏的”。列表支持分页、搜索和类型筛选。
2. 点击“添加任务”，可粘贴 `https://i.jielong.com/fb/xxx`、短 ID `xxx` 或数字 `ThreadId`。网站先通过详情接口解析真实 `ThreadId`，再打开表单。
3. 如需修改已提交内容，点击“我的已有记录”，选择本人可编辑的记录。
4. 水印相机接受本地照片，合成时间、地点、经纬度、右下角品牌与“真实时间”标识；也可以关闭水印，直接使用原图。
5. 点击“预览并准备提交”验证表单并上传附件，核对预览后再确认提交。

同一微信账号在多个浏览器或地点登录**同一套工作台服务**后，任意一处重新扫码取得的新 Token 都会供其他已登录设备使用。Token 过期不会清除设备上的账号记忆；已显示失效的页面会在返回前台或约 30 秒检查时自动恢复，正在编辑的内容保留。浏览器会话按最近访问续期一年；主动退出、清除 Cookie、会话记忆到期或使用另一套独立服务后，需要重新扫码。新访客不能仅凭账号名称或 ID 恢复登录。

点击页面右上角的“退出登录”可退出当前浏览器的微信账号，电脑和手机均可操作；登录失效时也可退出，再扫描另一个账号登录。退出后返回登录首页，其他设备与已启用的自动签到不受影响；停止自动签到请先在“自动签到”中暂停计划。演示空间的同一位置显示“退出演示”。

“水印工作室”可独立使用，照片合成与下载均在浏览器中完成。“演示空间”不发送真实签到，适合测试完整流程。

手动添加的任务集中显示在侧栏的“手动添加”分类，按真实 `ThreadId` 去重，并持久保存到本地 SQLite。保存记录绑定微信账号，刷新页面、重启服务或退出后重新登录同一账号仍然保留；不同账号分别保存。任务详情始终通过当前登录状态读取。

同时支持 `https://jielong.com/s/…` 分享链接：服务端读取公开重定向，得到最终接龙或打卡地址后，再解析真实 `ThreadId` 并保存。分享跳转不携带账号凭证，最多跟随五次官方站点跳转。

图片支持 JPEG、PNG、WebP；支持上传视频、音频、文件和签名图片。位置可以手动填写地址与经纬度，也可以在浏览器授权后读取设备坐标；设备坐标系不做自动转换。常见文本、数字、选项和日期字段提供表单控件，复杂矩阵等字段保留结构化编辑入口，其服务端协议尚未逐类验证。

## 循环自动签到

在周期打卡（`ThreadType=5`）详情中点击“启动循环签到”，核对待办后选择“保存并启动循环签到”。计划默认暂停，确认保存后才启用；默认每天北京时间 **18:00** 执行，可以单独调整为 00:00–22:59。

- 侧栏“自动签到”集中显示计划、当天结果与最近记录，可编辑今天或明天的待办、调整时间、暂停循环。
- 每日新待办从**本人昨天的签到记录**复制署名、编号和字段值；找不到昨天记录时使用空表单，必填项未完成不能启动。编辑待办不会修改历史记录。
- 图片和视频按原附件复用，照片保留已经合成的水印；需要更改图片内容或水印时重新上传。新附件先保存在本机，执行时才上传至接龙管家。
- 后端每 30 秒检查计划，执行前重新核对官方表单和本人今日记录；今天已签到时不重复提交。任务尚未开放时每 5 分钟重新检查，以原平台权限为准。
- 登录过期时显示“等待重新登录”，使用原微信账号在任意已连接同一服务的设备扫码后继续，其他已登录设备自动同步。仅在设定时间至当天 **23:00** 之间核对并补交，不补交往日记录。
- 提交失败或结果不明时停止当天自动重试，保留站内结果。提交过程中服务重启也不会盲目重发，请在官网核对。
- 计划、待办、附件、执行状态均保存在 `.local/`，同一账号重新登录和服务重启后保留。浏览器的自动暂存需点击保存后才成为后台执行的待办。

关闭网页后仍可执行，**需要保持本机服务运行**。暂停停止后续自动提交，已经发出的请求仍可能完成。退出网页登录不会删除或停止已启动的计划，请在“自动签到”中暂停。

### 可选邮件通知

**不要求配置邮箱。** 通知邮箱留空、地址不完整或 SMTP 配置不完整时，自动使用站内模式，照常执行签到；登录失效后在网站重新扫码即可。

如需邮件，在忽略提交的 `.env` 中填写 `SMTP_HOST`、`SMTP_USER`、`SMTP_PASS`，按服务商填写 `SMTP_PORT` 与 `SMTP_SECURE`，再在计划中填写接收邮箱。`TO_EMAIL` 是创建计划时的默认接收地址，`EMAIL_FROM_NAME` 是发件人显示名。

邮件覆盖签到结果、登录失效提醒、扫码恢复通知。通知持久化去重，发送失败至少间隔 10 分钟重试，最多五次；不影响签到执行。站内可以查看邮件发送状态。服务在发送邮件时中断的通知标为待核实，避免重启后重复发送。

设置 `BASE_URL` 为邮件接收设备可访问的工作台地址（默认 `http://127.0.0.1:3210`）。邮件链接只打开网站，不直接触发签到；登录续期仍通过网站的微信二维码完成。演示计划不发送真实表单或邮件。

## 接口适配

| 功能                  | 接口 / 结构                                                      |
| --------------------- | ---------------------------------------------------------------- |
| 微信登录              | 微信二维码轮询、`/api/User/OpenAuth`                             |
| 我的任务              | `/api/Thread/Threads`，参与 `1`、发布 `2`、收藏 `5`              |
| 接龙 / 签到表单       | `/api/FeedBack/GetEditFeedBackRecord`                            |
| 接龙 / 签到新建与修改 | `/api/FeedBack/AttendFeedBack`                                   |
| 打卡表单              | `/api/CheckIn/EditRecordDetail`                                  |
| 打卡新建与修改        | `/api/CheckIn/EditRecord`                                        |
| 水印照片              | `FieldType=25`，照片放入 `RecordValues[].Files`                  |
| 媒体上传              | 新申请 `CosUploadPolicy`，使用临时签名上传 COS，回填完整附件信息 |

打卡单独携带 `DateTarget`、`MinuteTarget`、`IsNameNumberComfirm`，保留字符串记录 ID。修改记录时从当前账号的新响应中获取编辑凭证，并在确认提交前检查表单与原记录是否发生变化。不会复用 HAR 中的 Token、Cookie、临时上传签名或他人记录。

协议依据用户提供的 `version2`、`shuiyin`、`shuiyin-2` 与 `daka` 抓包；HAR 本身没有复制进项目。

## 数据与校验

- 登录凭证与本地暂存附件位于忽略提交的 `.local/`；Cookie 使用 HttpOnly 和 SameSite=Strict。
- 草稿与选中的文件保存在当前浏览器的 IndexedDB；成功提交后清除对应草稿。
- 预览有效期 10 分钟；同一预览重复确认不会重复提交。
- 网络异常导致提交结果不确定时，先到官网核对记录，再决定是否重新提交。
- 本站依照原平台返回的任务权限、开放状态、字段限制与审核结果处理请求。

可用 `JIELONG_DATA_DIR` 指定本地数据目录，`FFPROBE_PATH` 指定媒体探测程序。若自行通过 HTTPS 反向代理部署，设置 `PUBLIC_ORIGIN=https://你的域名`，用于来源检查和 Secure Cookie。
